Draw a square with a loop (20 min session)

Left pane, you work. Right pane, Claude is your tutor.

Lesson 2 is about loops, so the first drawing is a loop you can see.

Open ~/course/square.py in nvim and type this. Before you run it, where do you think the turtle ends up, and which way will it face?

import turtle

t = turtle.Turtle()
for side in range(4):
    t.forward(100)
    t.left(90)

turtle.done()

Run it from fish:

python3 square.py

turtle.Turtle() makes a pen. forward(100) walks 100 steps and draws a line. left(90) turns 90 degrees to the left. turtle.done() keeps the window open until you close it. Ctrl+C stops it from the terminal.

Was your guess right? Where did the turtle end up?

To check your understanding: what would the picture look like if the loop ran 3 times instead of 4? Decide before you read on.

It draws three sides, a U shape, and the turtle stops one side short of where it started. The turns of 90 degrees only close the shape when there are four of them.

NoteTry it yourself

Change the loop so it draws a square with sides of 50. Then draw a row of three squares side by side. Where do you think each one starts? Guess before you run it. The change is in the lines inside the loop.

Colour and a row of squares

Add a colour before the loop:

t.color("blue")

Your guess: does the colour change the shape, or only the line? Run it and see.

Now draw the same square three times, with a for loop around the whole thing, and move the turtle between squares with t.penup(), t.forward(150) and t.pendown(). Where will the third square end up? Guess, then run it.

Ask Claude for the angle

A nonagon has nine sides, and the turn at each corner is 360 divided by nine. What number do you expect? Then add these lines to square.py, after the square’s loop and before turtle.done(). They use the pen t that the square already made. Running them on their own, as a new file, fails with NameError: name 't' is not defined:

import subprocess

reply = subprocess.run(
    ["claude", "-p", "How many degrees does a turtle turn at each corner of a nonagon? Reply with only the number.", "--no-session-persistence"],
    capture_output=True, text=True)
angle = float(reply.stdout.strip())
for side in range(9):
    t.forward(60)
    t.left(angle)

Was Claude’s number the one you predicted? The program does not know the answer; it trusts the reply and uses it. Your job is to check.

Aside: mv and rm

You have cp from lesson 1. Two more file commands finish the set. In ~/course, make a copy and move it:

cp square.py square2.py
mv square2.py shape.py
ls

Before ls, predict its output. Then remove the file:

rm shape.py
ls
Warningrm is permanent

mv replaces a file that already has the new name, without asking. rm removes a file with no trash and no u. Read the name twice before you press Enter.

Name a shape, and Claude gives its angle (25 min session)

Now input() drives the drawing. You type a shape’s name, Claude works out the turn at each corner, and the turtle draws it.

The question to Claude is an f-string: f"... {name} ..." puts the value of name into the text. You will use this form from now on. It replaces the + and str() joining you may have seen elsewhere.

import subprocess
import turtle

t = turtle.Turtle()
name = input("Name a shape (blank to stop): ")
while name != "":
    reply = subprocess.run(
        ["claude", "-p", f"How many degrees does a turtle turn at each corner of a {name}? Reply with only the number.", "--no-session-persistence"],
        capture_output=True, text=True)
    angle = float(reply.stdout.strip())
    t.clear()
    for side in range(round(360 / angle)):
        t.forward(60)
        t.left(angle)
    name = input("Name a shape (blank to stop): ")
turtle.done()

Guess, for a pentagon, what turn Claude gives and how many sides the program draws. The line round(360 / angle) works out the sides from the angle.

Type pentagon, then hexagon, then press Enter on an empty line.

For the bug:

  1. Write down the error message.
  2. Read what Claude sent back. Is it a number?
  3. Fix the program so it still works when Claude sends a sentence, or change what you ask. Decide which, and say why.

A playlist that asks Claude for lengths (25 min session)

Type song names. Claude gives each song’s length, and the program adds it to the running total. Run it first exactly as written, with no changes:

import subprocess

total = 0.0
song = input("Song name (blank to stop): ")
while song != "":
    reply = subprocess.run(
        ["claude", "-p", f"How many minutes long is the song {song}? Reply with only the number, like 3.5.", "--no-session-persistence"],
        capture_output=True, text=True)
    minutes = float(reply.stdout.strip())
    total = total + minutes
    print(f"{song}: {minutes} min, so far {total} min")
    song = input("Song name (blank to stop): ")
print(f"playlist total: {total} minutes")

Guess what the first song’s line prints, and the total after two songs. Then type a real song you know, and a title that doesn’t exist.

Watch what comes back. It can be a number, a sentence, or a request to look through your files. Claude is an agent: it can look things up in your folders as well as answer from memory. The program only sees text, so it cannot tell which one happened. When it crashes, read the error, and ask Claude in the right pane: “Did you search my files to answer that?” Guess its answer first.

WarningSay no when it asks

If Claude asks permission to read a folder, say no unless you know why it needs that folder.

The correction: answers from memory only

The lookup needs only what Claude already knows, so turn the tools off. Add two items to the call, "--tools", "", like this:

reply = subprocess.run(
    ["claude", "-p", f"How many minutes long is the song {song}? Reply with only the number, like 3.5.", "--tools", "", "--no-session-persistence"],
    capture_output=True, text=True)

Run it again with the made-up title. Guess first: does Claude send back a number or a sentence now? --tools "" turns every tool off, so the call can only answer from memory. Claude may still be wrong, so the check below still matters.

Claude is only guessing at song lengths, so check one of them on a phone or a streaming app. Did Claude get it right?

Bug hunt: a playlist that stops at 3.5

Claude wrote this version, and it has one bug. Run it with a song that is 3.5 minutes long, and find the bug. Claude will not say where it is.

import subprocess

total = 0
song = input("Song name (blank to stop): ")
while song != "":
    reply = subprocess.run(
        ["claude", "-p", f"How many minutes long is the song {song}? Reply with only the number, like 3.5.", "--no-session-persistence"],
        capture_output=True, text=True)
    minutes = int(reply.stdout.strip())
    total = total + minutes
    print(f"{song}: {minutes} min, so far {total} min")
    song = input("Song name (blank to stop): ")
print(f"playlist total: {total} minutes")

For the bug:

  1. Write down the error message, and what Claude sent back.
  2. Guess why int fails on a decimal, in one sentence.
  3. Fix it, run it, and check the total by hand.

Write an agent (25 min session)

This time Claude is in the game. Write a guessing game where Claude is the guesser and your program is the referee. Claude writes none of the code; it only guesses.

Your program:

  • picks the secret, a number you choose in the code. Claude never sees it;
  • each turn, sends Claude the guesses and hints so far, and asks for its next guess with claude -p, with "--tools", "" as in the playlist session;
  • checks Claude’s reply: is it a number? is it right? is it too high or too low? (if, elif, else, and int());
  • stops when Claude is right, or after 5 turns, with a while loop;
  • prints one * per turn left with a for loop, and the result at the end.

Claude remembers nothing between calls, so your program must send the whole history every turn. That is the agent part: the program decides the next step, and the model only answers.

Before you run it, make a guess: how many turns does Claude need if the secret is 50, and does it guess 25 first?

Each run uses a few calls from the weekly budget, so run it once or twice, not ten times.

AI thread: let Claude pick the secret

Claude can pick the secret for you. Add this to the top of the guessing game, in a copy, and replace your secret line with it:

import subprocess

result = subprocess.run(
    ["claude", "-p", "Pick a secret whole number from 1 to 50. Reply with only the digits.", "--tools", "", "--no-session-persistence"],
    capture_output=True, text=True)
secret = int(result.stdout.strip())

Guess: will two runs of the game pick the same secret?

Each call to Claude remembers nothing about the last one. The secret survives only because it is stored in secret, a variable in your program. Guess what happens if you move the subprocess lines inside the while loop, then run it.

WarningBug hunt waiting in this one

Claude’s reply is text, not always just digits. If it answers Sure! 27, the int(...) line fails. Run the game several times until it does, read the error, and decide where a program should check what a model sent back.
